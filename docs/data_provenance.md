# Data Provenance

What data this repository contains, where it comes from, and what it is **not**.

---

## 1. Summary

| Dataset | Location | Origin | Real platform data? |
|---|---|---|---|
| Course catalogue (12 rows) | `data/courses/courses.csv` | Hand-written for this project | **No — synthetic / illustrative** |
| Synthetic users | `data/synthetic/sim_users.json` (generated) | Our simulator | **No — synthetic** |
| Simulated interactions | `data/synthetic/interaction_logs.jsonl` (generated) | Our simulator | **No — synthetic** |
| Interaction logs (dev) | PostgreSQL `interactions` | Local testing only | **No** |

**There is no real Alfa-Kurs user, course or transaction data in this repository.**
Nothing here is a production export, a scrape, or a sample obtained from Alfa-Bank.

## 2. Course catalogue

- **Origin:** written by the project team to mirror the *kinds* of courses an
  entrepreneurship platform offers (marketing, sales, finance, management,
  programming, entrepreneurship).
- **Status:** `synthetic`. The `source` column carries this value for every row.
- **Titles and descriptions** are plausible but invented. Prices and durations are
  illustrative, not real Alfa-Kurs prices.
- **Purpose:** make retrieval, features and the demo concrete without needing a
  private catalogue dump.
- **Replacement:** a real catalogue can replace the CSV if it has the same columns;
  no code change is required. Update the `source` column to the real provenance
  (e.g. `curated:alfa-kurs`) and note the date.

### Schema

| Column | Required | Type | Validation |
|---|---|---|---|
| `course_id` | yes | string | unique, non-empty |
| `title` | yes | string | non-empty |
| `description` | yes | string | non-empty, used by retrieval |
| `title_ru` | no | string | localized title |
| `category` | yes | string | one of the configured categories |
| `skills` | yes | string | `;`-separated, non-empty |
| `objectives` | no | string | `;`-separated |
| `difficulty` | yes | string | beginner / intermediate / advanced |
| `duration_minutes` | yes | integer | > 0 |
| `price` | yes | number | >= 0 |
| `has_free_material` | yes | boolean | true / false |
| `source` | yes | string | `synthetic` or a documented real provenance |

### Validation rules

- duplicate `course_id` → reject the whole load
- negative price or non-positive duration → reject
- unknown `difficulty` or `category` → reject
- empty `title` / `description` / `skills` → reject
- `source` missing → reject (provenance is mandatory)

## 3. Synthetic users

Generated by `experiments/synthetic_users.py`.

- Fields: `user_id`, `industry`, `business_stage`, `experience`, `goals`,
  `budget_sensitivity`, and a **hidden** `preferences` vector.
- `hidden_preferences` exists only in the simulator. It is never written to the
  `users` table and never enters the feature vector.
- Reproducible from a seed; parameters are recorded in `run_manifest.json`.

## 4. Simulated interactions

Generated by `experiments/environment.py` from hidden preferences plus stochastic
noise. They are labeled as simulated in every output. They are not suitable for
inferring real user behavior.

## 5. Privacy

- No personal data: no names, emails, phone numbers, payment details.
- No user IDs that map to real people.
- The behavioral schema stores only anonymous ids, course ids and event types.

## 6. Honesty rules

1. Never describe synthetic rows as Alfa-Kurs data.
2. Every chart, table and slide produced from this data says **simulated**.
3. If real data is added later, record its origin, date, license and any filtering
   applied — in this file, in the same commit.
4. Do not quietly delete the `source` column to make data look real.

## 7. Reproducing generated data

```bash
python scripts/run_experiments.py --users 200 --rounds 50 --seeds 10 --seed-base 42
```

`data/synthetic/run_manifest.json` records seed, parameters and timestamp so any
reported number can be regenerated and audited.
